How it works

The math, in plain words

What "likely range" means

Test a different set of examples and you'd count a different number of mistakes. The likely range covers every real error rate that could plausibly have produced your count, at 95% confidence: build ranges this way over and over, and about 95 in 100 contain the real rate. Measured, that holds on average. Small tests at very low real rates miss more often, but those misses overstate the mistakes, the safe side.

Why not "6% ± a margin"?

The textbook formula says 0 mistakes in 7 examples gives a range of exactly 0% to 0%, which is the overconfidence this tool exists to catch. This calculator uses Wilson's score interval instead. It stays honest at small counts and at 0%: a perfect 7 really means "somewhere up to about 35%."

How many examples

A new test's rate wobbles around the real one. Planning for the size where your current rate would just squeak under the target works only about half the time. So the calculator works out the exact chance of success at each size, and suggests the smallest test that clears your chosen chance at that size and every size above it.

Comparing two versions

Checking whether two ranges overlap is a common shortcut, and it's too cautious. It misses real improvements. This calculator builds a range for the difference itself (Newcombe's method), and calls the change real only when that whole range is on one side of zero.

Same examples both times

When both versions ran on the same examples, the ones that came out the same say nothing about the change. Only two counts do: the examples it fixed and the ones it broke. The matched check (Tango's score interval, which agrees with McNemar's test) weighs just those, so it can see changes that separate-tests math blurs away.

Same math as my eval harness

Every rate in workflow-eval-harness is reported with this same range, so the two tools agree to the decimal. Nothing you type here is sent anywhere.
